Three things keep a long job alive.

Long agent runs go wrong the same way: the context fills, the chat gets summarised, and the summary drifts from what actually happened. On a tracked task, Yazi keeps the record outside the chat.

A fresh context that doesn't pretend.

A tracked task is one from a spec you attach with /spec. For it, Yazi rebuilds the model's context from the record: the objective, your constraints word for word, the latest checkpoint and the evidence it cites. Earlier episodes and summaries are left out, because that's where long runs drift.

Work has an owner, and a revision.

Each task is written down with its owner and a revision number that only goes up. Every save says which revision it started from, so a worker holding stale information is refused instead of overwriting newer work.

It writes down what it learned.

Run /refine and Yazi reviews the session, then proposes small edits to its own memories, prompt notes, skills and subagent specs. /refine apply lands them; every edit is revisioned, and /refine undo rolls back the last set.

What you can do with Yazi

Resume a saved task

Return to a session with yazi --continue; the full transcript stays searchable. A tracked task also brings its checkpoint, so the next round starts from what's recorded.

Run it somewhere else

A named SSH endpoint moves the shell, files, Python and processes to another machine. Credentials and history stay on your laptop.

Bring your own agent

Point a session at Claude Code, Codex or OpenCode. The agent keeps its own login. Yazi supplies the tools, the sandbox and the transcript. Switch back and its turns are ordinary history.

Tools for longer jobs

Read less, know more

Reading a file to find out what is in it is how an agent wastes context. index returns the skeleton instead, so the model reads only the lines that matter.

Built to hit the cache

When a file like AGENTS.md changes, Yazi appends a note instead of rewriting the prompt, so the provider's cached prefix survives. In a churn benchmark, this change took Yazi's warm cache rate from 11% to 98%.

Subagents with their own context

The model spawns subagents, each with its own context, Python runtime and model settings. They run in parallel and survive the parent compacting.

Prompt and forget

Give it a goal and walk away. Completion gates are real commands, go test or git diff --check, that have to pass before it stops. A failure feeds output back and it keeps going.

A sandbox that doesn't nag

Seatbelt on macOS, rootless runc on Linux, deny-default out of the box. It asks once for a resource and remembers the answer.

One session, two surfaces

The TUI and the web UI are the same runtime. Start the web surface, then scan the pairing code printed by Yazi to open the same session on your phone.

Nix as a tool source

In a sandboxed session with Nix available, the agent runs nix shell nixpkgs#<package> instead of installing with npm, pip, brew or apt, so nothing lands in the sandbox.

A plugin system that runs Doom

Plugins run out of process, are usually written in Python, and can add tools, commands, hooks, UI and model providers. That's enough surface to run Doom.
